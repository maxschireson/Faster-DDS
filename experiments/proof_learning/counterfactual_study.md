# Learning when to deviate from DDS ordering

Promoting DDS's second, third, or fourth choice can shorten a complete exact
solve. A first experiment finds 5.38% aggregate search-work savings from the
best tested **single** change within the first three card plays. A small model
trained on these interventions does not yet select them reliably: the reserved
family uses 2.21% more nodes and 7.42% more CPU time. Stock DDS remains the default.

## Experimental question

Train a correction to DDS's ordering: given the double-dummy position, current
proof target, original legal move ordering, and depth from the requested root,
should choice 2, 3, or 4 be tried before choice 1? The target is the work needed
to finish the entire root request, including all legal-move scores. A move can
be useful because it gives a cheaper successful proof, not only because it
avoids a failed branch. Labels come from sampled worlds already generated by
self-play; additional teacher solves run offline.

## Counterfactual teacher

Each trial changes exactly one decision encounter, then uses stock DDS for the
rest of the solve. It reproduces the identical search prefix and checks the
state key, complete stock move list, and encounter index before promoting a
candidate. Repeated target tests at the same state are separate encounters.
The rank-one control must reproduce the baseline node count exactly. Every
completed alternative must preserve every legal move's exact score.

The sample is 100 large requests from ten self-play deal families, with at
least ten tricks remaining. The budget per trial is max(20,000, four times
baseline recursive calls). Budget exhaustion produces a censored lower bound,
never a fabricated exact cost. No production self-play process was changed.

| Decisions sampled per root | Alternative trials | Best single change: node reduction | Roots with >5% opportunity |
| --- | ---: | ---: | ---: |
| First four encounters, first three card plays | 812 | 1.01% | 8/100 |
| Eight costliest encounters, first three card plays | 1,592 | 5.38% | 40/100 |
| Eight costliest encounters, first twelve card plays | 1,730 | 6.33% | 43/100 |

The three baselines each total 4,266,720 recursive calls. The corresponding
hindsight minima total 4,223,736, 4,037,037, and 3,996,525. There was one censored
trial in the twelve-play sweep and none in the other two. All completed trials
matched all-move scores. Some single changes saved nearly half of one solve's
work.

These are hindsight opportunities, excluding teacher cost, not trained-model
speedups. Offline cost prioritization intentionally spends labeling effort on
expensive encounters; their future cost is never an inference input or gate.
The depth comparisons sample different encounters and are not nested sets.
Twelve plays means up to twelve cards from the requested root, which may begin
mid-trick. Testing one change does not bound what coordinated two- or
three-decision changes could achieve, nor the opportunity in untested choices.

## First residual model

`train_delta.py` trains a 480→64→3 ReLU MLP with 30,979 parameters. Inputs are
the existing 427 position/target/legal-move features, 52 inverse stock-rank
features, and relative ply. Outputs predict log(alternative whole-root nodes /
stock whole-root nodes) for stock ranks 2, 3, and 4. Stock choice 1 has value
zero. Untested ranks are masked; aborted trials use a one-sided loss respecting
their lower bound. A Huber loss weights examples by the square root of baseline
work, with a cap. Neither baseline work nor measured outcomes enter the model.

Training combines the first-encounter and costly-encounter three-play sweeps:
1,033 unique observations after removing 142 duplicated encounters. Splits are
eight training families (830 rows), one validation family (89), and one test
family (114). Exact states plus stock ordering shared across splits are removed;
none occurred here. Validation loss selected epoch 2 of 80. The best validation
label loss only slightly beats always predicting zero, and test loss is worse.

Native inference inspects at most the first 64 eligible encounters, only within
three card plays and only for requests with ten or more tricks remaining. It
changes at most one decision per complete root, choosing a tested alternative
only when its prediction is below -0.02 (about a 2% node reduction). This fixed
threshold was set before the native result was inspected. No measured future
cost, oracle encounter index, or candidate outcome is available to this hook.

The complete native choice, including feature construction, takes approximately
0.96 microseconds with warm weights on this CPU. NumPy and C++ predictions agree.
This is a kernel measurement, not a portable latency guarantee; as many as 64
queries may be made for one solve.

## Causal whole-root evaluation

Evaluation uses the original 1,000 scavenged requests, not just the 100 teacher
roots. Baseline and guided solves alternate order, with three repetitions each;
timing includes the inference hook and search. The reported counts below include
all three repetitions. The 423 large requests are eligible for guidance; smaller
requests bypass it. All legal move scores matched on every comparison.

| Family partition | Requests | Baseline nodes | Guided nodes | Node change | CPU time change |
| --- | ---: | ---: | ---: | ---: | ---: |
| Training families | 800 | 96,298,962 | 96,549,177 | +0.26% | -0.08% |
| Validation family | 100 | 2,450,586 | 2,463,339 | +0.52% | +0.22% |
| Reserved test family | 100 | 4,221,579 | 4,314,939 | +2.21% | +7.42% |
| All families | 1,000 | 102,971,127 | 103,327,455 | +0.35% | +0.19% |

The test comparison is 0.581901 versus 0.625052 CPU seconds. It is one family
and a short timing sample, so the runtime percentage is noisy. The deterministic
node regression and failure to improve test label loss both argue against
deployment. All-family totals include training families and must not be used as
evidence of generalization. These families were reused during earlier research,
so even the reserved-family result is development evidence, not a fresh final
confirmation. The source sample lacks club contracts.

## Next experiment

Collect the same labels from many more independent self-play deal families,
retaining a random background sample alongside expensive decisions. Use a fresh
family holdout for the next decision. Examine the false promotions that create
slow refutations; a local position omits search history and transposition-table
context, which may affect the cost of an otherwise identical intervention.

For promising roots, extend the offline teacher to a small beam of two or three
conditional deviations, replaying the whole root to capture their interaction.
The teacher should retain alternatives that reduce verification work even when
both the old and new moves prove the same bound. A model continues to reorder
legal moves only: DDS remains responsible for proof and exact scores.

## Reproduction and validation

Apply `native.patch` to pinned DDS revision
`0f969b86a4841f438fd0cdff2924c4f2404abf6a`, then build the existing Bazel targets
`//benchmarks:proof_learning` and `//library/tests/ab_search:proof_model_test`.

```
proof_learning intervene refutation.roots interventions.jsonl 3 4
proof_learning intervene refutation.roots interventions_cost3.jsonl 3 8 cost
proof_learning intervene refutation.roots interventions_cost12.jsonl 12 8 cost
# Concatenate the two three-play files into delta_training.jsonl.
OPENBLAS_NUM_THREADS=1 python train_delta.py delta_training.jsonl delta_model
proof_learning delta all.roots delta_evaluation.jsonl delta_model/delta.txt -0.02
```

Seventeen Python tests and five native C++ tests passed, including independent
DDS checks of 425 older cutoff labels, intervention controls, inference parity,
abstention, inference limits, and unchanged exact scores. Newly added tests were
run failing before their implementations. Bazel analysis remained unavailable
in this environment (exit 255); the experiment rebuilt the changed translation
unit and linked the pinned checkout's existing static archives with GCC C++20,
`-O3 -Wall -Wextra -Werror`. C++ test sources used `-O0` because optimizing
GoogleTest exceeded the available memory. Full clean Bazel CI still needs to
pass. The configured clangd/Serena integrations were unavailable; compiler
diagnostics and native tests supplied local validation.

`counterfactual_summary.json` contains numeric results and training metadata.
Raw trials, root fixtures, the exact exported model, and evaluation rows are
preserved separately in `DDS_Counterfactual_Ordering_2026-11-09.zip`.
